# Documentation Entry Point

This file is the starting map for reproducing the artifact. The repository now
has several Markdown files with different roles; use this guide to choose the
right one.

## Start Here

- `README.md`: main user guide. It explains setup, dependency tiers, repository
  layout, and the supported commands for packaged figure redraws, GOAL/LGS
  runs, Composite-LP, Monolithic-LP, and NSYS-to-GOAL regeneration.
- `docs/figure_reproduction_status.md`: concise per-paper-figure status table.
  It says which figures are only redrawn from packaged CSVs and which ones have
  data/model regeneration evidence, including numeric match quality.
- `docs/revalidation_report.md`: final evidence-oriented report. It summarizes
  what was reproduced, which workloads run end-to-end, which sidecars are
  required, which runs were skipped as too expensive, and the remaining gaps.
- `docs/progress_log.md`: chronological lab notebook. It records commands,
  inputs, outputs, runtimes, memory use, comparisons, and root-cause notes.

## Reproduction Workflows

### Final Scratch Rerun Evidence

Use this when you want the strongest local evidence gathered in the final
high-RAM pass. It starts from existing GOAL files, NCCL metadata sidecars, and
NSYS/SQLite inputs, then writes fresh caches and regenerated outputs under
`/mnt/scratch/SC_Tracing_final_scratch_rerun_20260627`:

```bash
python3 scripts/final_scratch_rerun_campaign.py --workers 8
python3 scripts/summarize_final_scratch_rerun.py \
  --results-dir results/final_scratch_rerun_20260627
```

Read:

- `results/final_scratch_rerun_20260627/final_scratch_summary.md`
- `results/final_scratch_rerun_20260627/task_summary.csv`
- `results/final_scratch_rerun_20260627/comparison_summary.csv`
- `results/final_scratch_rerun_20260627/grok_node_scaling/`
- `new_results/final_scratch_rerun_20260627/`

### End-To-End Composite-LP From NCCL Metadata

Use this when `collective_instances.csv` and `comm_ring_info.csv` are available:

```bash
python3 pipeline/run_nccl_composite.py \
  --analysis-dir path/to/analysis \
  --out results/my_run/composed_runtime.csv \
  --cache-dir results/my_run/collective_cache \
  --clear-cache --parallel-solve --max-workers 8
```

Read:

- `README.md`, section `Run the paper-style NCCL Composite-LP path`
- `docs/revalidation_report.md`, sections `Data-Level Revalidation Matrix` and
  `Grok Node-Scaling Comparison`
- `results/revalidation/figures_end_to_end/figure_end_to_end_summary.md`

### GOAL To LP With `comm_dep.csv`

Use this when you need Monolithic-LP or GOAL-level Composite-LP. These paths
require an LP dependency sidecar generated by patched LogGOPSim:

```bash
python3 pipeline/run_lgs.py \
  --goal path/to/output.goal \
  --L 4000 --G 0.04 --o 200 \
  --comm-dep-out path/to/comm_dep.csv

python3 pipeline/run_monolithic_lp.py \
  --goal path/to/output.goal \
  --comm-dep path/to/comm_dep.csv \
  --out results/my_run/full_runtime.csv
```

Read:

- `README.md`, sections `LP sidecars` and `Run Monolithic-LP`
- `docs/revalidation_report.md`, section `comm_dep sidecar issue`
- `docs/progress_log.md` entries for Grok N4/N8/N16/N32/N64 and vLLM sidecar
  generation

### Raw NSYS/SQLite To GOAL And Sidecars

Use this only when you have NSYS-exported SQLite inputs and want to regenerate
GOAL plus NCCL metadata sidecars:

```bash
python3 pipeline/run_nccl_generator.py \
  --sqlite-dir path/to/nsys_sqlite_dir \
  --out-dir path/to/analysis
```

Read:

- `README.md`, section `Optional NSYS to GOAL regeneration`
- `docs/revalidation_report.md`, vLLM online NSYS and Fig. 5 rows
- `results/revalidation/vllm_online_nsys/summary.md`
- `results/revalidation/fig5_from_nsys/summary.md`

### Grok Node-Scaling Plot

Use this for the requested Grok node-count plot with hardware, LGS, and
Composite-LP series:

```bash
python3 scripts/grok_node_scaling.py \
  --out-dir new_results \
  --nodes 4 8 16 32 64 128 256 512 \
  --target-latency 0 \
  --target-latencies 0 4000 10000 250000 500000 1000000 \
  --no-packaged-large \
  --exclude-monolithic
```

- `new_results/grok_node_scaling_report.md`

## How To Interpret The Docs

- If you need commands to run: start with `README.md`.
- If you need a figure-by-figure answer: read
  `docs/figure_reproduction_status.md`.
- If you need evidence for a claim: read `docs/revalidation_report.md`.
- If you need exact command history, timings, memory, and deviations: read
  `docs/progress_log.md`.
- If you need the Grok scaling outputs directly: read `new_results/` or
  `results/revalidation/grok_node_scaling/`.

## Size Policy For Published Artifacts

Small result CSVs, JSON summaries, plots, and Markdown reports are suitable for
Git. Large raw traces, full GOAL bundles, solver scratch directories, txt2bin
caches, and large LP sidecars should not be committed unless explicitly agreed.
For example, `data/revalidation/grok_N64_commdep_lgs/comm_dep.csv` is hundreds
of MB and is intentionally excluded from the small publication bundle.
