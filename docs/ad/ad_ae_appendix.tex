\section{Overview of Contributions and Artifacts}

\subsection{Paper's Main Contributions}

\begin{description}
\item[$C_1$] We characterize the latency, bandwidth, and jitter
sensitivity of AI communication workloads at scales up to 4,096 GPUs.
\item[$C_2$] We introduce a compositional linear-programming method
with signature-based reuse for practical large-scale analysis.
\item[$C_3$] We use the results to derive network performance envelopes
and identify useful provisioning points.
\end{description}

\subsection{Computational Artifacts}

The evaluation uses two artifacts:

\begin{description}
\item[$A_1$] Code, input data, scripts, and results:
\url{https://github.com/tommasobo/SC26_ProvisioningAINetworks},
branch \texttt{artifact\_freeze}.
\item[$A_2$] Public execution traces:
\url{http://storage2.spcl.ethz.ch/traces/ai/}.
\end{description}

\section{Artifact Identification}

\newartifact

\artrel

Artifact $A_1$ contains the analysis implementation, plotting data,
reproduction scripts, verification manifests, and final plots. The
quick workflow generates Figures 1 and 3--10. Figure 2 is a method
diagram. The full workflow additionally runs the analysis and validation
stages for Figures 3--6.

\artexp

The quick workflow should produce eight PDF files under
\texttt{figures/}. The full workflow should also produce result CSV
files, logs, and task summaries in the selected scratch directory. The
generated curves should follow the paper results. Detailed numerical
comparisons are provided in
\texttt{docs/REPRODUCTION\_REPORT.md}.

The artifact assumes that execution traces have already been collected.
It does not launch model training or trace collection.

\arttime

Allow 15--30 minutes for installation. The quick workflow takes about
one minute. Allow up to eight hours for the full workflow, depending on
the machine, solver license availability, and worker count. Most
individual analysis tasks should be allowed up to one hour. The optional
Grok 4k latency and bandwidth analysis should be allowed approximately
3 to 5 days.

\artin

\artinpart{Hardware}

The quick workflow needs one CPU core, 2 GB of RAM, and about 100 MB of
free space. For the full workflow, we recommend at least 4 CPU cores,
32 GB of RAM, and a scratch filesystem. No GPU is required. The optional
Grok 4k analysis should use a large-memory node with at least 512 GB of
RAM and sufficient scratch space.

\artinpart{Software}

Python 3.10 or newer is required. Python packages are listed in
\texttt{requirements.txt}; full verification also uses
\texttt{requirements-dev.txt}. The full analysis requires Gurobi and a
valid license. The LogGOPSim example additionally uses \texttt{g++},
\texttt{gengetopt}, and \texttt{re2c}. Slurm is optional.

\artinpart{Datasets / Inputs}

The repository contains the numerical and processed inputs needed by the
default workflows. Large trace and intermediate files should be kept on
a scratch filesystem. Public traces are available from
\url{http://storage2.spcl.ethz.ch/traces/ai/}. Input identities are
recorded under \texttt{local\_artifact/manifests/}.

\artinpart{Installation and Deployment}

\begin{verbatim}
git clone https://github.com/tommasobo/\
SC26_ProvisioningAINetworks.git
cd SC26_ProvisioningAINetworks
git checkout artifact_freeze
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
\end{verbatim}

For the full workflow, also install
\texttt{requirements-dev.txt} and confirm that Gurobi can obtain a
license.

\artcomp

Run the quick workflow locally:

\begin{verbatim}
./reproduce_quick.sh
\end{verbatim}

Run the full workflow with a scratch directory:

\begin{verbatim}
./reproduce_full.sh \
  --scratch /scratch/$USER/provisioning_artifact \
  --workers 4
\end{verbatim}

On Alps, submit the analysis through Slurm:

\begin{verbatim}
./reproduce_full.sh --slurm \
  --account <account> --partition normal \
  --scratch /iopsstor/scratch/cscs/$USER/artifact \
  --workers 4
\end{verbatim}

The optional Grok 4k analysis is enabled only with
\texttt{--expensive\_run} and an explicit N1024 input directory. Before
enabling it, confirm that the selected partition provides at least
512 GB of RAM and a multi-day wall-time limit.

\artout

The quick workflow writes the final PDFs under \texttt{figures/}. The
full workflow writes one summary per task together with result CSV files
and logs in the selected scratch directory. Compare the produced files
with the values in \texttt{docs/REPRODUCTION\_REPORT.md}. The visual
comparison is in
\texttt{docs/comparison/SC26\_paper\_vs\_artifact.pdf}.

\newartifact

\artrel

Artifact $A_2$ contains the execution traces used to build communication
graphs and exercise the analysis pipeline for Figures 3--6.

\artexp

A selected trace should download with the recorded hash and pass through
the trace-processing and simulation stages. The repository includes the
input identities and reference results used by the final workflow.

\arttime

Allow up to one hour for a selected trace download and replay. Processing
a larger trace set can take several hours.

\artin

\artinpart{Hardware}

Use one CPU node with at least 32 GB of RAM and a scratch filesystem.

\artinpart{Software}

The trace workflow uses \texttt{curl}, SQLite, the repository's Python
tools, and LogGOPSim. NSYS is needed only when exporting a new report.

\artinpart{Datasets / Inputs}

The public traces are available at
\url{http://storage2.spcl.ethz.ch/traces/ai/}. Filenames and SHA-256
hashes used by this artifact are recorded under
\texttt{local\_artifact/manifests/}.

\artinpart{Installation and Deployment}

Install Artifact $A_1$, select one trace recorded in the manifests, and
download it to scratch. Do not store large trace files in the repository
or the home directory.

\artcomp

Follow the trace-processing commands in \texttt{docs/provenance/}. The
workflow converts the selected input into a communication schedule,
replays it with LogGOPSim, and writes a result CSV.

\artout

Record the downloaded file's SHA-256 hash and the generated result. These
values can be compared with the committed manifest and reference output.

\appendixAE

\arteval{1}

\artin

Clone branch \texttt{artifact\_freeze}, create the Python environment,
and install \texttt{requirements.txt}. For full validation, install
\texttt{requirements-dev.txt}, verify the Gurobi license, and choose a
scratch directory. On a cluster, use a compute allocation or the Slurm
launcher.

\artcomp

First run:

\begin{verbatim}
./reproduce_quick.sh
\end{verbatim}

Confirm that Figures 1 and 3--10 are generated. Then run either the local
full command or the Slurm command from the AD section. Do not add
\texttt{--expensive\_run} for the standard evaluation. The full workflow
runs the Figure 3--6 analysis tasks and compares their outputs with the
provided reference values.

\artout

Confirm that the eight expected PDF files exist under \texttt{figures/}.
For a full run, inspect \texttt{summary.json}, the task summaries, and the
result CSV files in scratch. Use
\texttt{docs/REPRODUCTION\_REPORT.md} for the expected numerical values.

\arteval{2}

\artin

Install Artifact $A_1$ and download one trace listed in the committed
manifests to scratch. Verify its SHA-256 hash before processing it.

\artcomp

Use the documented trace workflow to produce a communication schedule,
replay output, and result CSV. A single moderate trace is sufficient to
check the pipeline.

\artout

Compare the input hash and replay result with the committed manifest and
reference output.
