\section{Overview of Contributions and Artifacts}

\subsection{Paper's Main Contributions}

\begin{description}
\item[$C_1$] We characterize the latency, bandwidth, and jitter
sensitivity of AI communication workloads at scales up to 4,096 GPUs.
\item[$C_2$] We introduce a compositional linear-programming method
with signature-based reuse for practical large-scale analysis.
\item[$C_3$] We use the results to derive network performance envelopes
and identify useful provisioning points.
\end{description}

\subsection{Computational Artifacts}

The evaluation uses two artifacts:

\begin{description}
\item[$A_1$] Code, input data, scripts, and results:
\url{https://github.com/tommasobo/SC26_ProvisioningAINetworks},
branch \texttt{main}.
\item[$A_2$] Public execution traces:
\url{http://storage2.spcl.ethz.ch/traces/ai/}.
\end{description}

\section{Artifact Identification}

\newartifact

\artrel

Artifact $A_1$ contains the analysis implementation, plotting data,
reproduction scripts, verification manifests, and final plots. The
quick workflow generates Figures 1 and 3--10. Figure 2 is a method
diagram. The full workflow runs the numerical analysis for Figures 3--6
and passes the generated CSV files to the paper-style plotters. When raw
NSYS reports are supplied, it first performs trace export, SQLite
conversion, and analysis-input generation.

\artexp

The quick workflow should produce nine PDF files under
\texttt{figures/}. The full workflow should also produce result CSV
files, logs, and task summaries in the selected scratch directory. The
generated curves should follow the paper results.

Execution traces are inputs to the artifact. The workflow does not launch
model training or trace collection.

\arttime

Allow 15--30 minutes for installation. The quick workflow takes about
one minute. Allow up to eight hours for the full workflow, depending on
the machine, solver license availability, and worker count. Most
individual analysis tasks should be allowed up to one hour. The optional
Grok 4k latency and bandwidth analysis should be allowed approximately
3 to 5 days.

\artin

\artinpart{Hardware}

The quick workflow needs one CPU core, 2 GB of RAM, and about 100 MB of
free space. For the full workflow, we recommend at least 4 CPU cores,
128 GB of RAM, and a scratch filesystem. No GPU is required. The optional
4,096-GPU Grok 4k analysis should use a large-memory node with at least
1 TB of RAM and sufficient scratch space.

\artinpart{Software}

Python 3.10 or newer is required. Python packages are listed in
\texttt{requirements.txt}; full verification also uses
\texttt{requirements-dev.txt} and \texttt{requirements-tierc.txt}.
The raw-trace path requires the \texttt{nsys} command from NVIDIA
Nsight Systems. The full analysis requires Gurobi and a valid license.
Academics can obtain a
free Gurobi license from
\url{https://www.gurobi.com/academia/academic-program-and-licenses/}.
The LogGOPSim example additionally uses \texttt{g++}, \texttt{gengetopt},
and \texttt{re2c}. Slurm is optional.

\artinpart{Datasets / Inputs}

Small trace inputs may be supplied with the artifact. Larger trace sets and
intermediate files should be kept on a scratch filesystem. Public traces are
available from \url{http://storage2.spcl.ethz.ch/traces/ai/}.
Input identities are recorded under \texttt{local\_artifact/manifests/}.

\artinpart{Installation and Deployment}

\begin{verbatim}
git clone https://github.com/tommasobo/\
SC26_ProvisioningAINetworks.git
cd SC26_ProvisioningAINetworks
git checkout main
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
\end{verbatim}

For the full workflow, also install \texttt{requirements-dev.txt} and
\texttt{requirements-tierc.txt}, then confirm that Gurobi can obtain a
license.

\artcomp

Run the quick workflow locally:

\begin{verbatim}
./reproduce_quick.sh
\end{verbatim}

Run the full workflow with a scratch directory:

\begin{verbatim}
./reproduce_full.sh \
  --scratch /scratch/$USER/provisioning_artifact \
  --workers 4
\end{verbatim}

On Alps, submit the analysis through Slurm:

\begin{verbatim}
./reproduce_full.sh --slurm \
  --account <account> --partition normal \
  --scratch /iopsstor/scratch/cscs/$USER/artifact \
  --workers 4
\end{verbatim}

The optional 4,096-GPU Grok 4k analysis is enabled only with
\texttt{--expensive\_run} and an explicit N1024 input directory. Before
enabling it, confirm that the selected partition provides at least
1 TB of RAM and a multi-day wall-time limit.

\artout

The quick workflow writes the final PDFs under \texttt{figures/}. The
full workflow writes one summary per task together with result CSV files
and logs in the selected scratch directory.

\newartifact

\artrel

Artifact $A_2$ contains the execution traces used as inputs to the
trace-to-plot workflow for Figures 3--6.

\artexp

A selected trace set, supplied with the artifact or downloaded from the
public repository, should pass through the trace-processing and numerical
analysis stages. The repository records the input identities used by the
workflow.

\arttime

Allow up to one hour for a selected trace download and replay. Processing
a larger trace set can take several hours.

\artin

\artinpart{Hardware}

Use one CPU node with at least 32 GB of RAM and a scratch filesystem.

\artinpart{Software}

The trace workflow uses \texttt{wget}, the \texttt{nsys} command,
SQLite, the repository's Python tools, and Gurobi. LogGOPSim is used by
the optional replay and Monolithic-LP stages.

\artinpart{Datasets / Inputs}

The public traces are available at
\url{http://storage2.spcl.ethz.ch/traces/ai/}.
Filenames and SHA-256 hashes used by this artifact are recorded under
\texttt{local\_artifact/manifests/}.

\artinpart{Installation and Deployment}

Install Artifact $A_1$ and prepare the selected trace set. Small trace sets
may be supplied with the artifact; download larger trace sets to scratch.
Do not store large traces in the home directory.

\artcomp

Run the selected trace workflow in a scratch directory. It exports the
NSYS reports to SQLite, constructs the communication schedule and
analysis inputs, runs the numerical analysis, and writes the result CSV
and plot.

\artout

Confirm that the downloaded file's SHA-256 hash, the generated result,
and the execution log are recorded in the output directory.

\appendixAE

\arteval{1}

\artin

Clone branch \texttt{main}, create the Python environment,
and install \texttt{requirements.txt}. For the full workflow, install
\texttt{requirements-dev.txt} and \texttt{requirements-tierc.txt}, verify
the Gurobi license, and choose a new scratch directory with sufficient
free space. We recommend 4 CPU cores and 128 GB of RAM. On a cluster,
use a compute allocation or the provided Slurm launcher.

\artcomp

Begin with the short installation and plotting check:

\begin{verbatim}
./reproduce_quick.sh
\end{verbatim}

This verifies the Python environment and generates Figures 1 and 3--10
with the submission plotting scripts. Figure 2 is a method diagram.

Run the main numerical workflow with:

\begin{verbatim}
./reproduce_full.sh \
  --scratch /scratch/$USER/provisioning_artifact \
  --workers 4
\end{verbatim}

The full workflow builds the analysis problems, runs the solver and
sensitivity sweeps for Figures 3--6, and writes fresh numerical results to
scratch. It then passes those CSV files to the paper-style plotters. The
generated PDFs use the same axes, labels, typography, and dimensions as the
paper figures.

For a trace-to-plot run, place the raw NSYS reports in the directory layout
described in the repository README and add the trace root. Small trace sets
may be supplied with the artifact; larger sets are available from Artifact
$A_2$ and should be downloaded to scratch.

\begin{verbatim}
./reproduce_full.sh \
  --scratch /scratch/$USER/provisioning_artifact \
  --trace-root /scratch/$USER/raw_traces \
  --workers 4
\end{verbatim}

This adds NSYS export, SQLite conversion, and communication-schedule
generation before the numerical tasks. The subsequent solver and plotting
steps use the outputs produced in that same run.

On a Slurm system, use the command from the AD section. The numerical
tasks are submitted independently. Their job identifiers are written to
\texttt{submitted\_jobs.txt}. Wait for all jobs and the final plotting
step to finish before inspecting the output. Do not enable
\texttt{--expensive\_run} during the standard evaluation.

\artout

A successful full run produces newly computed CSV files, one JSON
manifest per analysis task, execution logs, and the final plot PDFs.
Confirm that every task manifest reports \texttt{status: ok} and that
Figures 1 and 3--10 are present under the scratch directory's
\texttt{figures/} subdirectory. The CSV files in scratch are the numerical
inputs used by the final plotting step.

\arteval{2}

\artin

Install Artifact $A_1$ and prepare the selected raw NSYS reports using the
directory layout described in the repository README. Use a supplied small
trace set or download a larger set from Artifact $A_2$. Keep large traces
and all intermediate files in scratch.

\artcomp

Run the general raw-trace workflow:

\begin{verbatim}
./reproduce_full.sh \
  --scratch /scratch/$USER/provisioning_artifact \
  --trace-root /scratch/$USER/raw_traces \
  --workers 4
\end{verbatim}

The workflow exports the NSYS reports to SQLite, constructs the GOAL
schedules and analysis metadata, runs the numerical tasks, and passes the
newly generated result CSV files to the paper-style plotting scripts.
Use the Slurm option from the AD section when running on a cluster.

\artout

Confirm that the SQLite exports, GOAL schedules, analysis metadata,
result CSV files, plots, manifests, and task logs were created in the
selected scratch directory.
