\section{Overview of Contributions and Artifacts}

\subsection{Paper's Main Contributions}

\begin{description}
\item[$C_1$] We characterize the latency, bandwidth, and jitter
sensitivity of AI communication workloads at scales up to 4,096 GPUs.
\item[$C_2$] We introduce a compositional linear-programming method
with signature-based caching for practical large-scale analysis.
\item[$C_3$] We use the results to derive network performance envelopes
and identify useful provisioning points.
\end{description}

\subsection{Computational Artifacts}

The evaluation uses two artifacts:

\begin{description}
\item[$A_1$] Code, compact data, scripts, and results:
\url{https://github.com/tommasobo/SC_Tracing}, branch
\texttt{artifact\_freeze}.
\item[$A_2$] Public input traces:
\url{http://storage2.spcl.ethz.ch/traces/ai/}.
\end{description}

\section{Artifact Identification}

\newartifact

\artrel

Artifact $A_1$ contains the solver, trace-processing tools, compact
plotting data, reproduction scripts, verification manifests, and final
plots. The quick workflow redraws Figures 1 and 3--10. Figure 2 is a
method diagram. The full workflow also runs bounded checks for Figures
3, 4, and 6 and verifies the closest recovered Figure 5 result.

\artexp

The quick workflow should produce eight PDF files under
\texttt{figures/}. The full workflow should also produce task manifests
and result CSV files in the selected scratch directory.

Figures 1, 7, and 10 are exact redraws of compact data. Figures 8 and 9
redraw the published values embedded in their plotting script. The
paper-style plots for Figures 3, 4, and 6 use the compact paper data,
while separate raw-derived checks record the reproducibility of those
experiments. The closest Figure 5 Composite curve differs from the paper
CSV by at most 0.014853\%.

The following limitations are documented in
\texttt{docs/REPRODUCTION\_REPORT.md}:

\begin{itemize}
\item the exact paper-era Figure 5 per-motif transformation was not
  recovered;
\item the available Figure 6 Llama metadata identify Llama 7B at 128
  GPUs, while the paper says Llama 70B;
\item the Figure 6 vLLM full curves require an unavailable paper-era
  token-window reduction; and
\item Grok at 4,096 GPUs is plot-only unless the expensive option is
  explicitly enabled.
\end{itemize}

\arttime

Installation takes about 10 minutes. The quick workflow takes under
5 minutes and took about 20 seconds on Alps. The default full workflow
takes under 6 hours with independent tasks submitted in parallel. Each
individual default experiment is bounded to about 45 minutes. Grok at
4,096 GPUs is excluded from this estimate.

\artin

\artinpart{Hardware}

The quick workflow needs one CPU core, 2 GB of RAM, and about 100 MB of
free space. The full workflow was tested on Alps CPU nodes. We recommend
4 or more CPU cores, 32 GB of RAM, and a scratch filesystem. No GPU is
required. The Grok 4,096-GPU analysis needs substantially more memory
and time and is disabled by default.

\artinpart{Software}

Python 3.10 or newer is required
(\url{https://www.python.org/}). Package versions are listed in
\texttt{requirements.txt}; full verification also uses
\texttt{requirements-dev.txt}. Fresh solver runs need Gurobi and a
license (\url{https://www.gurobi.com/}). LogGOPSim is included in the
repository and additionally uses \texttt{g++}, \texttt{gengetopt}, and
\texttt{re2c}. Slurm is optional.

\artinpart{Datasets / Inputs}

Compact data are committed under \texttt{data/},
\texttt{local\_artifact/results/}, and
\texttt{results/reproduced/}. Hashes and raw-input identities are under
\texttt{local\_artifact/manifests/}. Large NSYS, SQLite, GOAL, solver
cache, and temporary files are intentionally kept outside Git.

\artinpart{Installation and Deployment}

\begin{verbatim}
git clone https://github.com/tommasobo/SC_Tracing.git
cd SC_Tracing
git checkout artifact_freeze
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
\end{verbatim}

For the full validation, also install
\texttt{requirements-dev.txt} and confirm that Gurobi can obtain a
license.

\artcomp

The default local check is:

\begin{verbatim}
./reproduce_quick.sh
\end{verbatim}

Run the full workflow from a scratch filesystem:

\begin{verbatim}
./reproduce_full.sh \
  --scratch /scratch/$USER/provisioning_artifact \
  --workers 4
\end{verbatim}

On Alps, submit independent tasks through Slurm:

\begin{verbatim}
./reproduce_full.sh --slurm \
  --account <account> --partition normal \
  --scratch /iopsstor/scratch/cscs/$USER/artifact \
  --workers 4
\end{verbatim}

The full launcher serializes the longest solver sweeps when needed to
respect license limits. Grok at 4,096 GPUs is run only with
\texttt{--expensive\_run} and an explicit N1024 analysis directory.

\artout

The quick workflow writes the final PDFs under \texttt{figures/} and
checks their presence. The full workflow writes one manifest per task,
fresh CSV files, logs, and a summary in the selected scratch directory.
The final comparison and known differences are in
\texttt{docs/REPRODUCTION\_REPORT.md}.

\newartifact

\artrel

Artifact $A_2$ contains the execution traces used to build communication
graphs and validate the analysis pipeline. It supports the trace-based
checks for Figures 3--6.

\artexp

A selected trace should download with the recorded hash and pass through
SQLite export, GOAL conversion, binary conversion, LogGOPSim replay, and
plotting. The repository includes provenance for the exact inputs used in
the final checks.

\arttime

A small trace download and replay takes about 5--45 minutes. Processing a
large campaign can take several hours and is not required for the
functional check.

\artin

\artinpart{Hardware}

Use one CPU node with at least 32 GB of RAM and a scratch filesystem.

\artinpart{Software}

The trace workflow uses \texttt{curl}, SQLite, the repository's Python
tools, and LogGOPSim. NSYS is needed only when exporting a new report.

\artinpart{Datasets / Inputs}

The traces are listed at
\url{http://storage2.spcl.ethz.ch/traces/ai/}. Exact filenames and
SHA-256 hashes used by this artifact are recorded under
\texttt{local\_artifact/manifests/}.

\artinpart{Installation and Deployment}

Install Artifact $A_1$, choose one trace recorded in the manifests, and
download it to scratch. Do not store large trace files in the repository
or the home directory.

\artcomp

Follow the commands in \texttt{docs/provenance/} for the selected trace.
The stages are NSYS or SQLite input, GOAL, binary schedule, LogGOPSim
replay, and CSV plotting. A moderate trace is sufficient for evaluation.

\artout

Record the downloaded file's SHA-256 hash, the replay runtime, and the
generated CSV. These values can be compared with the committed manifest
and reference result.

\appendixAE

\arteval{1}

\artin

Clone branch \texttt{artifact\_freeze}, create the Python environment,
and install \texttt{requirements.txt}. For full validation, install
\texttt{requirements-dev.txt}, verify the Gurobi license, and choose a
scratch directory. On a cluster, use a compute allocation or the Slurm
launcher rather than a login node.

\artcomp

First run:

\begin{verbatim}
./reproduce_quick.sh
\end{verbatim}

It redraws Figures 1 and 3--10 from the committed compact inputs and
validates the data manifests. Then run either the local full command or
the Slurm command from the AD section. Do not add
\texttt{--expensive\_run} for the normal evaluation.

The main checks are:

\begin{itemize}
\item Figures 3 and 4: compare the fresh bounded runs with the selected
  raw-derived results and the paper CSVs;
\item Figure 5: verify the selected 201-point Composite CSV and its
  maximum relative error of 0.014853\%;
\item Figure 6 Llama: run the bounded latency and bandwidth checks with
  four physical NIC queues; and
\item Figure 6 vLLM and Grok 4k: inspect the committed replay evidence
  and compact data. These are not rerun by default.
\end{itemize}

\artout

Confirm that the eight expected PDF files exist under \texttt{figures/}.
For a full run, inspect \texttt{summary.json}, the task manifests, and
the result CSVs in scratch. Use
\texttt{docs/REPRODUCTION\_REPORT.md} for the expected error values and
the interpretation of remaining differences.

\arteval{2}

\artin

Install Artifact $A_1$ and download one trace listed in the committed
manifests to scratch. Verify its SHA-256 hash before processing it. The
Llama-3.1-8B vLLM trace is the most complete end-to-end example.

\artcomp

Use the documented trace pipeline to produce SQLite, GOAL, binary, and
LogGOPSim outputs. A single archived vLLM job point is enough to check
the pipeline. The available online 70B trace is not a substitute for the
paper-era vLLM input.

\artout

Compare the input hash and replay runtime with the committed manifest.
The archived vLLM point should replay exactly. The full sensitivity
curve is expected to differ because the paper-era token-window reduction
is unavailable.
